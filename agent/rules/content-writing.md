# 記事の書き方

対象: `docs/**/*.md`(記事を書く・直すとき)。

## 文章

- 記事は日本語で書く。コマンド、コード、ファイルパス、技術用語は英語のままにする。
- 「最近」「現在」「以前」「今は」などの相対的な時間表現は使わない。時点が分かるように、日付で書く(例: `2026-11-21 時点で…`)。
- 外部の文章を引用する場合は、出典を明記する。

## ページの構成

- 新しいページには、フロントマターを付けない(`date` は Hugo の名残で、使っていない)。既存ページの `date` も更新しない。
- 作成日と最終更新日(`git_creation_date_localized`、`revision_date`)は、デプロイ時に CI が Git の履歴から挿入する。手で書かない。
- 製品やサービスのページは、H1 の直後に、公式サイトへのリンクを置く。
- 新しい節は、そのページの既存の並び(時系列なら古い順など)に合わせて置く。決まった並びがなければ、末尾に足す。

## Markdown の書式

- 記事間のリンクは、`.md` への相対パスで書く(例: `[systemd](../software/systemd/index.md)`)。
- 注意書きは admonition(例: `!!! note`)で書く。
- コードブロックには、言語を指定する。シェルのコードは、文脈に応じて `sh`、`bash`、`zsh`、`fish` から選ぶ。スクリプト言語の前提がなく、サンプルコマンドなどを書くときは、`bash` を既定とする。
- Markdown のライブラリ(Python-Markdown)の制約に従う。
  - リストの入れ子は、4スペース単位で字下げする(2スペースでは入れ子にならない)。
  - 段落の直後にリストを書くときは、空行を1行挟む。
  - 同じ階層で、箇条書き(`-`)と番号付き(`1.`)を続けて書かない。
