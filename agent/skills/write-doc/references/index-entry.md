# インデックスの項目の書き方

`agent/index/` の1行を書く規則。目的は、記事を書くときに、置き場所を判断できるようにすること。

## 形式

- 1ページ1行で、`` `パス` — 概要 ``。パスは `docs/` からの相対パス(例: `cli/jq.md`)。
- セクションページ(`docs/<dir>/index.md`)も、ほかのページと同じく1行にする。ディレクトリ単位の概要の行は設けない。
- 並び順は、`zensical.toml` の `nav` の順に合わせる(`draft` の出力の順)。
- ファイルの先頭に、対象を示す見出し(例: `# docs/network/ のインデックス`)を置く。
- `docs/memo/` は対象外。

## 書く内容

- 「何について、何が書いてあるか」を書く。
- 題材が H1 やパスから明らかなときは、繰り返さない。
- 近くに紛らわしいページがあるときだけ、境界を添える(例: 「UEFI は別ページ」)。
- URL、個別の手順、日付は書かない。本文を読まないと言えない推測も書かない。

## 長さと文体

- 全角60字以内。`check` が、超えたものを警告する。
- 体言止めか名詞句。日本語で、技術用語は英語のまま。
- 並列項目が多いときは、「分類語 + 代表例3〜5個 + など」にする。全項目は列挙しない。
  - 例: `git サブコマンド別の使用例(branch、commit、log、rebase、remote、tag など)`
- 列挙が2〜3個のときは、全部書く。
- 「定義」「概要」のような、題材の説明だけの語は避ける(例: `ハッシュ関数の定義。SHA-256` ではなく、`SHA-256 など、ハッシュ関数の例`)。

## 材料

- 主な材料は、H1 と H2。`draft` の出力にある。
- 汎用的な見出し(About、はじめに、Tips、参考 など)は、括弧付きで出る。見出し自体は材料にしない。
- 汎用的な見出しの直後の数行は読む(例: `grep -n -A 4 -E '^## (About|Usage)' <ページ>`)。名前だけでは何か分からないもの(例: `hub`)は、これで対象が何かを確かめてから書く。行は、最後まで読む(`cut` などで途中で切らない)。
- `description` は補助。URL のみのものは使わない。文章のものは、見出しと矛盾しなければ参考にする。記事側の `description` は、インデックスのために書き換えない。
- `flags` の意味:
  - `review`: 意味のある H2 がない。本文の冒頭を読んで書く。読んでも判断できないときは、ユーザーのレビューで確認する。
  - `small`: 15行以下の小さいページ。H1 と本文の冒頭1文から書く。
  - `url-desc`: `description` が URL。使わない。
- 本文がほぼない、または引用だけのページは、括弧で状態を添える(例: `(本文はほぼなし)`、`(用語辞典からの引用)`)。

## 書いたあと

- `uv run python scripts/docindex.py check` で、エラーがないことを確認する。
  - 「項目がない」: ページに対応する行がない。
  - 「実体がない項目」: 行はあるが、ページがない。
  - 「項目が重複」「置き場所が違う項目」: 行の重複と、書く場所の誤り。書く場所は、トップレベルのディレクトリ `<dir>` の `agent/index/<dir>.md`(分割したときは `<dir>/` 配下)。`docs/` 直下のページは `index.md`。
  - 「概要が未記入」: `TODO` のまま残っている。
  - 「項目が多い」(警告): 1つのインデックスのファイルが、上限(80項目)を超えた。下の「分割するとき」に従って分割する。
  - 「表のページ数が実数と違う」(警告): `agent/index/index.md` などの一覧表のページ数が、`docs/` の実数とずれている。表を直す。
- 推測を含む概要には、レビューで確認してほしい点を、ユーザーへの報告に書く。

## 分割するとき

- 1ファイルの目安は80ページまで。トップレベルのディレクトリの配下が80ページを超えたら、`agent/index/<dir>.md` を `agent/index/<dir>/index.md` と `agent/index/<dir>/<sub>.md` に分ける。
  - `<dir>/index.md`: `docs/<dir>/` 直下のページと、サブディレクトリごとのファイルの一覧。
  - `<dir>/<sub>.md`: `docs/<dir>/<sub>/` のインデックス。
- 分割したら、`agent/index/index.md` の表のリンク先を、`<dir>/index.md` に直す。ページ数は、`docs/<dir>/` 配下の実数にする。`<dir>/index.md` の表には、サブディレクトリごとのページ数を書く。
