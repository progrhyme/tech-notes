# 2026-11-25

## 11/25
### Oh My Zsh を廃止して、Starship に移行した

#### 経緯

シェル環境から [Oh My Zsh](../../cli/shell/zsh/ohmyzsh.md) を外して、[Starship](../../cli/shell/starship.md) に移した。起動の遅さと、設定が膨らむことが気になっていた。AI エージェントもこのシェルで動くため、POSIX 互換の zsh は、そのまま使う。fish などの POSIX 非互換のシェルは、AI が生成する Bash 前提のコードと、食い違いやすい。

#### 判断

候補は、Starship と、プラグインマネージャの Sheldon だった。Starship はプロンプト、Sheldon はプラグインの管理で、役割が違う。併用もできる。

Oh My Zsh 経由で使っていたプラグインは、`zsh-autosuggestions` の 1 件だけだった（`zsh-syntax-highlighting` は、Oh My Zsh を介さず、Homebrew のものを直接読み込んでいた）。管理するものが少ないため、Sheldon は入れず、Starship だけにした。

#### 結果

- プロンプトは、Starship に置き換わった。
- 起動時間は、短くならなかった。`zsh -i -c exit` を 5 回ずつ測り、どちらも 0.54 から 0.59 秒だった。目的のうち、起動の速さは、達成していない。
- Oh My Zsh が暗黙で与えていた設定、キーバインド、エイリアスの一部が、なくなった。必要になったときに戻せるよう、内容を [Oh My Zsh](../../cli/shell/zsh/ohmyzsh.md#暗黙で有効になる設定) のページに書き残した。

#### 外すときの注意

- `zsh-autosuggestions` は、Oh My Zsh がなくても使える。Homebrew で入れて、`.zshrc` で `source` する。

    ```zsh
    source "${HOMEBREW_PREFIX}/share/zsh-autosuggestions/zsh-autosuggestions.zsh"
    ```

- プラグイン `shrink-path` の `shrink_path -f` は、パスを fish のように縮める。Starship では、`directory` の `fish_style_pwd_dir_length` で、近い表示になる。
- Oh My Zsh が暗黙で有効にしていた設定のうち、必要なものは、`.zshrc` に明示する。

### zsh の対話シェルの設定を、実際の環境に触れずに比べる

設定を変える前後で、`setopt`、`bindkey`、`alias`、起動時間を比べたかった。普段使っているシェルには触れずに、次の方法で比べた。

1. 偽の `HOME` を作り、その下に、設定ファイルへのシンボリックリンクを並べる。差し替えたい設定だけを、前後で別のものにする。
2. その `HOME` を指定して、`zsh -i` を、擬似端末で起動する。
3. 起動後に、`setopt | sort`、`bindkey`、`alias` を出力して、前後で `diff` を取る。

設定ファイルが、端末に接続されているか（`-t 0 && -t 1`）で、対話用の設定を読み分けていた。擬似端末でないと、対話用の設定が読まれない。

#### 擬似端末の作り方でつまずいた点

- `script` コマンドは、標準入力がソケットのとき、`tcgetattr/ioctl: Operation not supported on socket` で失敗する。Python の `pty.fork()` で、擬似端末を作って、出力を集めた。
- `script` の標準出力を `/dev/null` にすると、中のシェルが対話シェルとして動かなかった。
- zsh では、`"$ref:envs"` の `:e` が、変数の修飾子（拡張子の取り出し）として解釈される。`"${ref}:envs"` と、波括弧で囲む。

### Starship の設定を、agnoster 風に寄せた

#### 経緯

最小限の構成（ホスト名、パス、Git、`❯`）にすると、見た目が寂しくなった。Oh My Zsh の agnoster テーマの見た目に近づけた。設定の全体は、[Starship](../../cli/shell/starship.md#agnoster-風の設定) のページに書いた。

#### 作り方

- セグメントの間の矢印は、直後のセグメントが表示されるときだけ出したい。そこで、前のセグメントが矢印を持つ形にした。
- Git リポジトリの内か外かで、最後のセグメントが変わる。内は `git_status` が、外は `custom` モジュールが、閉じ矢印を出す。
- `git_status` は、Git リポジトリの中でしか動かない。閉じ矢印を、`format` の括弧の外に置くと、変更がないときも、矢印だけが出る。

#### 限界

agnoster は、変更の有無で、Git のセグメントの背景色（緑と黄）を変える。Starship の `style` は、状態では切り替わらない。背景は緑に固定して、状態は記号（`●`、`✚`、`…`）で示した。

#### 詰まった点

TOML に、powerline の矢印（U+E0B0）を、文字として書いたところ、書き込みの途中で欠けて、矢印が出なかった。`"\ue0b0"` のエスケープで書くと、解決した。

### gcloud-prompt を、Starship に対応させた

#### 背景

[gcloud-prompt](https://github.com/progrhyme/gcloud-prompt) は、gcloud の設定名とプロジェクトなどを、プロンプトに出す自作のツール。シェル関数 `gcloud_prompt` の出力を、`PROMPT` に埋め込んで使う。`toggle_gcloud_prompt` で、表示と非表示を切り替えられる。

Starship は、プロンプトを外部プロセスで組み立てる。シェル関数と、export していないシェル変数は、そのままでは見えない。

#### 方式

次の 2 つを検討した。

| 方式 | 内容 | 採否 |
| :--- | :--- | :--- |
| `custom` モジュール | `gcloud_prompt` を呼ぶ実行可能スクリプトを、`command` に指定する | 不採用 |
| 環境変数 + `env_var` モジュール | プロンプトの前に、`gcloud_prompt` の出力を環境変数に export して、`env_var` モジュールで出す | 採用 |

`custom` は、`gcloud-prompt.sh` を読み込むたびに `gcloud info` を実行するため、プロンプトを描くたびに別プロセスで読み込むと、遅くなる。

採用した方式のために、関数 `gcloud_prompt_export` を追加した。`gcloud_prompt` の出力を、`GCLOUD_PROMPT_TEXT` として export する。zsh では、`precmd_functions` に登録する。

```zsh
precmd_functions+=(gcloud_prompt_export)
eval "$(starship init zsh)"
```

`starship init zsh` が組み立てる前に実行したいので、`precmd_functions` への登録を、`starship init` より先に書く。

`starship.toml` の側は、`env_var` モジュールで出す。

```toml
[env_var.GCLOUD_PROMPT_TEXT]
variable = "GCLOUD_PROMPT_TEXT"
style = "bg:cyan fg:black"
format = "\n[ ☁ $env_value ]($style)[\ue0b0](fg:cyan)\n"
```

書式に改行を含めると、gcloud の情報が、プロンプトの上の行に出る。

#### 不具合

`toggle_gcloud_prompt` で非表示にすると、`GCLOUD_PROMPT_TEXT` が、空文字で export されたままになった。`env_var` モジュールは、変数が空でも書式を出すため、`☁` の記号だけが残った。

非表示のときは、空にせず、`unset` するようにした。モジュールは、書式の改行を含めて消える。

#### リリース

バージョン 0.7.0 として、タグ `v0.7.0` を打った。リポジトリの慣習に合わせた。

- `CHANGELOG.md` に、バージョンの項を足す。
- `gcloud-prompt.sh` の `GCLOUD_PROMPT_VERSION` を更新する。
- コミットのメッセージは、バージョン（`0.7.0`）にする。
- 注釈付きのタグ `v0.7.0` を打つ。

テストは、シェルスクリプトのテストランナー [shove](https://github.com/progrhyme/shove) で、Bash と zsh の両方で動かした。タグは、スカッシュマージの後の既定ブランチに打つ。作業ブランチのコミットは、スカッシュで消えるため。

シェルスクリプトのパッケージマネージャ [shelp](https://github.com/progrhyme/shelp) で入れている環境では、`shelp update` で取り込める。

### Homebrew の接頭辞を、固定で書かない

読み込みのパスを `/usr/local/share/...` と書いていたため、`zsh-syntax-highlighting` が、読み込まれていなかった。Apple Silicon の Mac では、Homebrew の接頭辞が `/opt/homebrew` で、Intel の Mac は `/usr/local` になる。

`brew shellenv` を評価すると、環境変数 `HOMEBREW_PREFIX` が設定される。パスは、`${HOMEBREW_PREFIX}/share/...` と書く。`brew --prefix` は、呼ぶたびに `brew` を起動して遅いので、使わなかった。

```zsh
eval "$(/opt/homebrew/bin/brew shellenv)"   # ~/.zprofile など。Apple Silicon の場合（Intel は /usr/local/bin/brew）

_highlighter="${HOMEBREW_PREFIX:-}/share/zsh-syntax-highlighting/zsh-syntax-highlighting.zsh"
[[ -r "${_highlighter}" ]] && source "${_highlighter}"
```

### 設定リポジトリの変更

公開している [dotfiles](https://github.com/progrhyme/dotfiles) では、共通のセットアップ関数にあった Oh My Zsh のインストール処理を、Ubuntu デスクトップ用の環境のディレクトリに移した。ほかの環境からは、Oh My Zsh を前提にしなくなる。
