- ローカルのテキストファイルで管理できる。

- 階層化（親子関係）がある。

- Web サーバなどで、可視化できる。

まず OSS を調べ、よさそうなものがなければ自作する方針にした。

#### Backlog.md を試した

[Backlog.md](../../software/backlog-md.md) のバージョン 1.57.4 を、npm で入れて試した（2026-11-23）。

- 階層: `--parent` で、4階層まで子タスクを作れた。
- Web UI: かんばんと一覧は、階層を表さず、平らに並ぶ。子タスクは、親の詳細の「Subtasks」欄に、直下の分だけ出る。木構造のビューはない。
- マイルストーン: タスクのまとまりを、マイルストーンで表すこともできる。CLI では、マイルストーンごとの完了数が見える。
- 約60件のタスクを、親タスク1つ、その子タスク、マイルストーン8つの構成で入れてみた。最初は、フェーズも子タスクの階層（親、実装、フェーズ、項目の4階層）で表したが、フェーズをマイルストーンにして、親と子の2段にしたほうが、見通しがよかった。

#### 判断

- Backlog.md を、いったん採用する。木構造のビューがない点は、後回しにする。自作するのは、必要になってからでよい。
- データのディレクトリは、Git の管理対象にする。履歴が残り、別のマシンにも同期できるため。

#### 運用で気をつけたこと

- 初期化: `--integration-mode none` を指定して、Backlog.md がエージェント向けの指示ファイルを書き換えないようにした。
- ファイル名: Backlog.md は、タイトルをそのままファイル名にする。日本語やバッククォートがファイル名に入るのを避けたかったので、設定を探した。設定はなく、コードで決め打ちされていた。
    - ファイル名を ID だけ、または ID と英語の slug に直接変えても、読み込めて、編集のあとも保たれる。
    - そこで、作成のあとに、ファイル名を整えるスクリプトを自作して使うことにした。
- マイルストーンの指定: タイトルで指定すると、別のマイルストーンに割り当たることがあった。ID で指定する。
- 直接の編集の禁止: データのディレクトリに `AGENTS.md` を置いて、CLI だけで操作するように書いた。

### Claude Code で、サブディレクトリの AGENTS.md が読み込まれるタイミングを試した

ディレクトリごとのルールを `AGENTS.md` に書いたら、そのディレクトリを操作するときに、Claude Code が認識するのかを、試した。

#### 試したこと

- 前提: 作業しているプロジェクトのルートには、`AGENTS.md` があり、`CLAUDE.md` はない。ルートの `AGENTS.md` は、会話の最初から読み込まれていた。
- サブディレクトリ `sub/` に `AGENTS.md` を作り、目印として、「返信の先頭に決まった文字列を書く」というルールを書いた。
- 作成した直後は、読み込まれなかった。
- `sub/` の中の既存のファイルを Read すると、その直後に、`sub/AGENTS.md` の内容が、追加の文脈として届いた。以降は、ルールに従って返信できた。

#### わかったこと

- サブディレクトリの `AGENTS.md` は、会話の最初からではなく、そのディレクトリのファイルを操作した時点で、読み込まれる。
- ファイルを書き込んだだけでは、読み込まれなかった。
- したがって、そのディレクトリで作業を始める前の判断には、効かない可能性がある。
- 試していないこと: `Bash` で `ls` をするだけの操作で、読み込まれるか。

#### 公式ドキュメントの記述

2026-11-23 に確認した、公式ドキュメントのメモリのページには、同じ挙動が書かれていた。

- サブディレクトリの `AGENTS.md` は、そのディレクトリのファイルを Read ツールで開いたときに読み込まれる。ただし、そのディレクトリに `CLAUDE.md` がないときに限る。
- サブディレクトリの `CLAUDE.md` は、そのディレクトリのほかのファイルを、読む、書く、編集したときに読み込まれる。

指示ファイルの置き場所や読み込みの条件は、[Claude Code のページ](../../software/coding-ai/claude.md)にまとめた。
